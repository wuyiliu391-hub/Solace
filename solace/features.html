Operit / execution layer

让角色
真的能帮上忙。

一个把自然语言、设备工具、代码工作区和角色上下文连接起来的 Agent 执行层。

The agent loop

每一步都
看得见。

Operit 的核心不是“能调用很多工具”，而是知道什么时候该调用、调用前要不要问、失败后怎么把真实结果带回对话。

01INTENT

识别任务

区分闲聊、剧情和明确设备/代码请求。

→
02ROUTE

选择路径

确定性路由优先，复杂任务再交给工具 Agent。

→
03GATE

获得授权

写入、编辑和命令等高影响操作需要确认。

→
04RESULT

返回事实

保留 stdout、错误原因和工具记录，不伪装成功。

Workspace Agent

代码工作区，
不是黑箱。

每个聊天可以绑定自己的项目目录。Agent 只接受工作区内的相对路径，并在写入前保存快照。恢复默认目录只是解除绑定，不会删除你的代码。

Workspace tools

读、写、改，
都有退路。

TOOL用途默认策略
list_directory查看工作区目录和文件摘要只读
read_file读取限定大小的文本文件只读
write_file创建或覆盖文件，并生成快照需授权
edit_file唯一原文匹配的精确编辑需授权
rollback_file使用工作区内快照回滚修改需授权
run_command在工作区根目录执行受限命令高影响
Role context

工具执行结束，
关系还在继续。

Operit 将工具结果作为真实上下文交还给角色：不是机械地说“任务完成”，而是让角色知道发生了什么、哪里失败、下一步需要谁决定。
