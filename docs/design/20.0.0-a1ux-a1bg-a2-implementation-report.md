### A1-BG（后台心跳）

| 变更 | 位置 |
|------|------|
| 心跳中追加 `_maintainAiLife(db)` | `background_service.dart` → `handleForegroundProactiveChatTask` |
| 新函数 `_maintainAiLife(Database db)` | 同上 |

**设计决策**：
- **复用调用方已打开的 db 连接**，不再单独 `openDatabase`（避免多实例、避免 initialize 反复调用）
- **幂等**：靠「当天日程已存在则跳过」「同一 block 已写过日志则跳过」双保险
- **失败隔离**：单个角色维护失败不影响其他角色

**心跳周期**：沿用现有 1 分钟前台心跳，无需额外 Timer。

### A2（主动分享 + 定时事件）

| 文件 | 说明 |
|------|------|
| `lib/models/life/timed_event.dart` | `TimedEventType` 枚举 + `TimedEvent` 模型（支持每年重复） |
| `lib/services/life/timed_event_service.dart` | 注册 / 查询未来 N 天 / 检查并触发 / 自动注册内置事件 |
| `lib/services/life/active_share_service.dart` | 判定当前是否该主动分享（`evaluate`）+ 记录分享（`recordShare`） |

**ActiveShareService 关键设计**：

| 条件 | 检查 |
|------|------|
| 当前有块 | `currentBlock != null` |
| 块允许分享 | `block.shareable == true` |
| 冷却未到 | 最近一条 `source='share'` 的 life_log 距今 ≥ 4h |
| 情绪合适 | 愤怒/悲伤 且强度 > 0.7 → 拒绝 |

**TimedEventService 关键设计**：
- `isToday` 支持一次性（完整日期比对）与重复（月日比对）
- `isWithin(now, N)` 检查 `[now, now+N-1]` 窗口
- `registerBuiltinsIfNeeded` 幂等注册生日
- `checkAndFire` 返回本次触发的事件列表，供上层决定是否通知

## 二、架构接续（A2 挂点已就绪）

心跳中的执行顺序：

```
handleForegroundProactiveChatTask（每分钟）
  ├── 遍历角色 → _handleProactiveChat（原有主动消息）
  └── _maintainAiLife(db)
        └── 遍历角色
              ├── 1. DailyScheduleService.getOrGenerate（今日日程，幂等）
              ├── 2. 找当前时间块
              ├── 3. 检查该块是否已写过日志
              ├── 4. LifeLogService.appendFromSchedule（写日志）
              ├── 5. ActiveShareService.evaluate + recordShare（分享判定+记录）
              └── 6. TimedEventService.checkAndFire（生日/纪念日）
```

**后续 A3（跨角色互访）可以直接挂在第 6 步之后**，不破坏现有顺序。

## 三、与规划的差异

| 规划 | 实际 | 原因 |
|------|------|------|
| `_maintainAiLife` 里新开 repo | 接受外部 db 参数 | 避免多实例/initialize 副作用 |
| `LifeLogService` 构造接受 repo | 接受 `Database` + 可选 `onSaveMemory` 回调 | 分层解耦：UI 层可传 `repo.saveMemory`，背景层传 null 也能跑 |
| `DailyScheduleService` 构造接受 repo | 接受 `Database` | 同上 |
| ActiveShare 直接推消息 | 只判定 + 记录日志 | 消息生成交给 ChatBloc 更合理，避免侵入现有 LLM 管线 |
| 定时事件触发 → 通知 | 触发 → 写日志 | 通知接入留待后续；先让时间轴可见 |
