## 一、交付清单

### 1. 新增数据模型（`lib/models/life/`）

| 文件 | 内容 |
|------|------|
| `daily_schedule.dart` | `LifeActivity` 枚举（11 种活动）、`ScheduleBlock`（时间块）、`ScheduleSource`、`DailySchedule` |
| `life_log.dart` | `LifeLogSource` 枚举、`LifeLog` 模型（含情绪、来源、记忆同步标记） |

**设计要点**：
- `ScheduleBlock.contains(hhmm)` 正确支持**跨零点区间**（如 23:00 → 07:00）
- `DailySchedule.blocks` 以 JSON 文本落库，解析失败时安全回退为空列表
- `LifeLog.source` 使用 `cross_visit` 作为 DB 存储值（下划线风格与项目一致），模型层用驼峰 `crossVisit`

### 2. 新增服务（`lib/services/life/`）

| 文件 | 职责 |
|------|------|
| `daily_schedule_service.dart` | 规则引擎生成日程；读取/更新当前时间块 |
| `life_log_service.dart` | 按日程块生成日志；`syncToMemory` 注入记忆库 |

**DailyScheduleService 关键设计**：

| 特性 | 实现 |
|------|------|
| **零 LLM 成本** | 完全规则生成，不需要网络 |
| **人设感知** | 关键词识别「夜猫型」/「早起型」，作息模板不同 |
| **工作日/周末区分** | 周末可能走 `outing` / `relax` 分支 |
| **稳定随机** | 用 `(characterId, date)` 派生种子，同一天多次读取结果一致 |
| **跨零点睡眠** | 睡眠块从 `sleepHour` 到 `wakeHour`，天然支持跨零点 |
| **8-11 个时间块** | 睡眠/起床/早/午/晚/工作/休息/晚间活动/睡前 |
| **分享标记** | 部分块带 `shareable: true` + `sharePrompt`，供 A2 的 ActiveShareService 消费 |

**LifeLogService 关键设计**：

| 特性 | 实现 |
|------|------|
| **每日上限** | `dailyLimit = 6`，防刷屏 |
| **睡眠块跳过** | 不给"我在睡觉"写日志 |
| **情绪着色** | 从 `CharacterEmotion.effectiveEmotion` 映射到中文语气后缀 |
| **记忆注入** | `syncToMemory` 用 `weight=0.5` 低权重 + `MemoryType.state`，ID 前缀 `lifelog_` 天然去重 |
| **日志来源可扩展** | `appendCustom` 支持 A2/A3 的 share / crossVisit |

## 二、与规划的差异

| 规划 | 实际 | 原因 |
|------|------|------|
| `DailyScheduleService.generateForDate` | 改名 `getOrGenerate` + `regenerate` | 前者自动读缓存，后者强制重生成，语义更清晰 |
| `DailyScheduleService.getCurrentBlock` | 参数从 `characterId` 改为 `AICharacter` | 内部需要人设生成日程 |
| LLM 润色入口 | 只留注释，未实现 | 规划 A1 阶段允许纯规则；留待 A2 或后续补 |
| 日志模板 | 按 block 类型 + 情绪后缀组合 | 简单可靠，避免首版就引入 LLM 成本 |

## 六、如何在有 Flutter 环境的机器上继续

```bash
# 1. 拉取静态分析
flutter analyze

# 2. 跑新增测试
flutter test test/life/

# 3. 跑全量测试确认无回归
flutter test

# 4. 真机 / 模拟器上验证迁移
flutter run
# 打开任意角色 → 触发 DailyScheduleService.getOrGenerate → 观察数据库
```

如果 analyze / test 报错，最可能的 3 个位置：
1. `DailyScheduleService` 里 `_EveningPick` 的 const 构造（如果 analyzer 要求更严格）
2. `life_log_service.dart` 中 `EmotionType` 枚举的 switch 穷举（已覆盖全部 13 个值）
3. `local_storage_repository.dart` 中 `expectedColumns` 新表的类型字符串（已对齐现有风格）
