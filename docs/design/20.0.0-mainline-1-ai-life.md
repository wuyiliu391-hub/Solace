# 20.0.0 主线一 · AI 主动生活

> 上级文档：[`roadmap-20.0.0.md`](../roadmap-20.0.0.md)
> 迭代：A1（日程+日志）→ A2（主动分享+定时事件）→ A3（跨角色互访）
> 数据库：v72 → v74

---

## 1. 设计目标

让每个 AI 角色拥有**独立于用户的一天**：

- 用户不在时，角色也在生活、工作、休息
- 用户回来时，能"回看"角色这段时间做了什么
- 角色会因经历而主动发起对话，而不是"沉默超时"
- 角色之间会互相串门，形成跨角色事件

**核心原则**：日程生成**本地规则优先**，LLM 只做润色，避免成本/耗电爆炸。

## 3. 服务设计

### 3.1 `DailyScheduleService`（A1）

```dart
class DailyScheduleService {
  /// 生成指定角色某天的日程
  /// 优先规则引擎；仅当角色开启"高级日程"时调用 LLM 润色
  Future<DailySchedule> generateForDate({
    required String characterId,
    required String userId,
    required DateTime date,
  });

  Future<DailySchedule?> getForDate(String characterId, DateTime date);

  /// 当前时间块（用于"她此刻在做什么"）
  Future<ScheduleBlock?> getCurrentBlock(String characterId);
}
```

**规则引擎**（本地，零成本）：
1. 读取角色人格（`ai_character.personality`）→ 决定作息类型（早起型/夜猫型）
2. 读取角色职业/背景（`backgroundStory`）→ 决定工作日/休息日模板
3. 引入随机扰动（±30 分钟），避免每天一模一样
4. 输出 8-14 个时间块

**LLM 润色**（可选，用户开关）：
- 输入：规则生成的骨架 + 角色人设
- 输出：给每个 block 更贴合人设的 `label`
- 每次只调 1 次 LLM，maxTokens ≤ 512

### 3.2 `LifeLogService`（A1）

```dart
class LifeLogService {
  /// 根据日程 + 情绪生成一条日志
  Future<LifeLog> appendFromSchedule({
    required String characterId,
    required String userId,
    required ScheduleBlock block,
    required String currentMood,
  });

  Future<List<LifeLog>> getRecent(String characterId, {int days = 7});

  /// 把已生成的日志同步进记忆库（去重）
  Future<void> syncToMemory(String characterId, String userId);
}
```

**日志生成策略**：
- 简单 block（如 `sleep` / `commute`）→ 模板句 + 情绪色彩
- 复杂 block（如 `work` / `social`）→ 可调 LLM 生成 1-2 句
- 每天最多生成 6 条日志（避免刷屏）
- 日志生成后**可选**注入 `MemoryEngine`（默认开启，权重较低）

### 3.3 `ActiveShareService`（A2）

```dart
class ActiveShareService {
  /// 判断当前时间块是否应该触发"主动分享"
  Future<ShareDecision> evaluate({
    required String characterId,
    required String userId,
    required ScheduleBlock block,
  });

  /// 执行分享：可发消息 / 发朋友圈 / 仅记录日志
  Future<void> execute(ShareDecision decision);
}
```

**触发条件**（全部满足才触发）：
1. `block.shareable == true`
2. 距上次分享 ≥ `AppDurations.shareCooldown`（建议 4 小时）
3. 角色情绪强度 ≥ 阈值（或 block 标了 `mustShare`）
4. 用户未开启免打扰 / 未在通话中

**分享内容生成**：
- 复用 `proactive_decision_engine` 的 LLM 通道
- 注入上下文：角色人设 + 当前日程块 + 当前情绪 + 最近记忆
- 输出：一句话 + 可选配图 prompt（主线三消费）

**分享去向**（三选一，可配置）：
- 直接发聊天消息（默认）
- 发朋友圈动态（`moments` 表）
- 只写日志不发（低打扰模式）

### 3.4 `TimedEventService`（A2）

```dart
class TimedEventService {
  Future<List<TimedEvent>> getUpcoming(String userId, {int days = 7});
  Future<void> register(TimedEvent event);
  Future<void> checkAndFire(String userId); // 由 heartbeat 调用
}
```

**自动注册**（系统内置）：
- 角色生日（从 `ai_character` 的 `birthday` 字段）
- 首次对话纪念日
- 关系升级纪念日
- 法定节日（本地硬编码）

**用户自定义**：设置页新增"纪念日管理"

### 3.5 `CrossVisitService`（A3）

```dart
class CrossVisitService {
  /// 检测是否应该发生互访（角色 A 去角色 B 家）
  Future<CrossVisit?> maybeTrigger({
    required String userId,
    required List<String> characterIds,
  });

  /// 执行互访：生成共同事件 + 双方对话摘要
  Future<CrossVisit> execute({
    required String hostId,
    required String guestId,
    required String userId,
  });
}
```

**触发条件**：
1. 至少 2 个角色开启了"主动生活"
2. 双方关系值 ≥ 阈值（依赖主线二的关系表；A3 阶段先用简化的"亲密度均值"）
3. 双方当前日程块都是 `social` 或 `rest`
4. 距上次互访 ≥ 24 小时

**执行流程**：
1. 读取双方人设 + 关系
2. 复用 `group_chat_prompt_pipeline` 生成 5-10 轮对话
3. 抽取关键摘要 → `summary`
4. 双方情绪值变化
5. 各自写入一条生活日志
6. （可选）通知用户："A 今天去了 B 家"

## 4. 与现有模块的接线点

| 现有模块 | 接线方式 |
|----------|----------|
| `background_service.dart` | 挂载每日 0:00 生成次日日程任务；每小时检查当前 block |
| `proactive_scheduler.dart` | 保留原有逻辑；新增日程驱动的分享入口 |
| `proactive_decision_engine.dart` | 决策上下文新增 `scheduleBlock` / `currentMood` / `recentLifeLog` |
| `proactive_action_executor.dart` | 新增 `ProactiveActionType.lifeLog` / `.activeShare` / `.crossVisit` |
| `emotion_engine.dart` | 日程事件 → 情绪变化（如 `work` → 疲惫累积） |
| `memory_engine.dart` | 生活日志进记忆库（低权重） |
| `ai_activity_service.dart` | 展示"她此刻在做什么"的数据源 |

## 8. 成本控制

| 项 | 策略 |
|----|------|
| LLM 调用 | 日程默认规则生成；日志每天 ≤ 6 条 LLM 润色；分享每次 1 调 |
| 后台耗电 | 日程生成只在 0 点一次；block 切换检查每小时一次 |
| 存储 | 日志保留 90 天，之后归档到记忆库后删除 |
| 网络 | 全部功能支持离线（LLM 不可用时降级为模板句） |
