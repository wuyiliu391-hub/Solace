# 群聊长期记忆滚动总结设计

## 目标

让群聊角色在长期对话后仍能记住重要事件、关系变化、约定和未完成话题，同时不改变现有自然激活、艾宾浩斯记忆和最近消息上下文行为。

## 设计

新增独立的 `group_chat_summaries` 表，每个 `groupId + chatId` 保留一条滚动总结。总结属于群聊分支，不写入 `social_memories`，避免混淆角色社交记忆与群级公共记忆。

字段：

- `groupId`：群聊 id
- `chatId`：聊天记录/分支 id
- `summary`：当前完整总结
- `messageCount`：生成总结时已覆盖的消息数量
- `updatedAt`：最后更新时间

采用 `(groupId, chatId)` 唯一约束或等价的更新查询，旧数据库通过幂等建表自动迁移。

## 数据流

1. 群聊回复落库后累计新增消息数。
2. 每累计 15 条新消息，在后台异步触发一次总结；不阻塞当前回复和 UI。
3. 读取旧总结及其 `messageCount` 后，取该位置之后的新消息。
4. 调用 AI 生成“旧总结 + 新消息”的完整更新总结，消息格式始终包含 `用户/角色名`。
5. 生成成功后覆盖同一 `groupId + chatId` 的总结并更新覆盖消息数；失败则保留旧总结。
6. 每个角色回复时，将该分支的群聊总结注入共享上下文；仍保留最近群聊消息、角色私密记忆和现有群内社交记忆。

## 约束

- 总结只描述群聊公共事实，不共享角色私密记忆。
- 分支之间不共享总结，避免聊天记录互相污染。
- 最近消息仍保留，滚动总结不是实时消息历史的替代品。
- 后台任务要捕获异常，不能影响 AI 回复。
- 导入旧备份没有总结表时，启动或首次访问自动建表即可。

## 测试

- 缺表时自动创建总结表。
- 同一 `groupId + chatId` 保存总结时更新而不是重复插入。
- 不同分支总结互相隔离。
- 消息数量未达到 15 条增量时不触发总结。
- 总结生成失败时保留旧总结。
- 群聊角色上下文包含当前分支总结。
